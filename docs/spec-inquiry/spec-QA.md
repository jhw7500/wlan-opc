에러 코드 관련
1. 패스워드 및 ESSID의 무효 문자 정의
2. SetIndication 로그인 조건 위반 0x0002 / 0x0013 역할 구분
3. List Boundary Flag에서 개시(start) 없이 계속(continue)/완료(end)만 수신한 비정상 시퀀스에 대한 Result/Error Cause가 정의가 없음

무선 설정 관련
1. 무선 설정 변경의 Result=OK가 (a) 설정값 기록 및 무선기 적용 완료를 의미하는지, 아니면 AP 재접속(실제 연결)까지 완료를 의미하는지(불휘발 저장 2분 응답 예산과 재접속 소요시간 산정에 영향)
2. 현재 ESSID는 IP 주소 리스트(§3.3.6)와 IP 주소 변경(§3.3.7)에 포함되어 있고, 무선 설정 변경(§3.3.8)에는 포함되어 있지 않음. ESSID는 무선 파라미터 성격이 강하므로 무선 설정 변경 쪽에 두는 편이 구현 및 운용에 있어 자연스러움. 현재 ESSID를 IP 리스트에 묶어 둔 설계 의도(IP 프로파일별 사이트 ESSID 연동 등)와 무선 설정 변경 측 이관 가능 여부 확인
3. 기판 정보의 802.11r, k, v, ai 값은 지원 여부를 뜻하는지 링크 상태를 조회하는 것인지 확인

네트워크 토폴리지 관련
1. 해당 문서에서 지칭하는 IP는 유선용인지 무선용인지 확인
- 무선 인터페이스는 별도 서브넷의 관리용 IP를 갖거나, IP를 두지 않음.
- 유선↔무선 간 사용자 데이터는 투명 L2 브릿지(유선측 MAC 동적 클로닝)로 전달되며, L3 라우팅/포워딩을 사용하지 않음. 따라서 위 관리 IP 설정과 무관하게 end-to-end 통신이 성립함.
- 유선·무선 관리 IP가 동일 서브넷이면 ARP 응답 경합이 발생하므로 서로 다른 서브넷이어야 함.
2. 투명 L2 브릿지 구성에서 장치는 L3 라우터가 아니므로(IP 포워딩 비활성, default route 없음) 기본 게이트웨이가 불필요. 게이트웨이 구성이 필요한 경우가 있는지 확인
3. Gateway와 NTP 서버가 없는 구성을 고려하여 미지정을 허용하는 방안 검토 요청
4. NTP 서버를 무선망 측 서버로 사용할 경우, VHL이 사용하는 서브넷이 아닌 다른 서브넷의 NTP 서버를 등록해야 함. 이를 인자하고 있는지 확인
5. 사양 확정을 위해, 실제 운용 라인에서의 네트워크 구성도 요청
 - 각 장치의 IP/서브넷마스크/게이트웨이/NTP 설정, AP 및 컨트롤러 구성을 포함한 토폴로지.

Indication 관련
1. 각 자원의 임계값 및 판정 방식(예: 사용률 % 기준), Current Val 단위 규정 필요(예: CPU/Disk = %, Network = Mbps)
2. Indication 형 메시지에 무선기(WLAN#1/#2) 식별 필드가 없음
3. 주기 통지(Indication Period>0) 시 한 주기 내에 사상(상태변화/로밍/절단 등)이 여러 번 발생할 경우 처리 방식이 미정의.

상태 및 동작 관련
1. IP 주소 변경 요청 후 자동 로그아웃의 경우 동작 방식(명시적 Logout 요구/응답이 없으므로, 대기 중이던 IP 주소 변경을 적용하지 않고 폐기)
2. Device Status의 기동 중 상태(0x00000000)에 대한 정의

기타
1. List Boundary Flag 값이 사양서 내에서 상충. 정확한 정의 확인
2. 공통 헤더(64바이트)는 고정부 8바이트 + Reserve 56바이트(바이트 8~63)로 구성된 것이 맞는지 확인
3. 리셋 요구의 응답 도면이 Length=0으로 표기되어 있으나, 동시에 Reserve(8~63) + Result/Error Cause(64~67) 필드를 포함
